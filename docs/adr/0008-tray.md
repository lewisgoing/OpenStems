# 0008: The tray icon and the quick-drop window

Date: 2026-11-22. Status: accepted.

This deviates from the plan, which describes one window.

## Decision

OpenStems lives in the Windows notification area. A click on its icon opens a small window
against the taskbar, the quick-drop window: drop a song on it, drag the stems out of it. The
full window is one click away and is no longer needed for the everyday case.

## The quick-drop window

- **What is in it.** The recipe and the quality, a drop target, and the recent jobs, newest
  first. A finished job has a handle that drags every stem. One finished job at a time lays
  its stems out as pills, each draggable on its own: the latest, until another job is clicked.
  A job with more than twelve stems shows twelve and sends the rest to the full app.
- **One queue, one choice.** It talks to the same engine as the full window, so both show the
  same jobs. The recipe and quality are the same choice in both: the selection is stored in
  `localStorage`, and each window follows the other through the `storage` event.
- **It stays open when it loses focus.** A drop always starts in another window (Explorer, a
  DAW's browser), so a window that hid on blur could never be dropped on. It goes away on a
  second click on the icon, on Escape, with its close button, or when the full app is opened.
  It is always on top, has no taskbar button and is not in Alt+Tab.
- **Where it sits.** Against the taskbar, centered on the tray icon, 12 px clear of the screen
  edges, on the screen the icon is on. The taskbar's edge is read from the work area; for a
  taskbar that hides itself, from the icon. When Windows gives no usable icon position the
  window goes to the tray corner. (`electron/traylogic.ts`, a pure function with tests.)
- **Same page, second window.** The window loads the same bundle with `?window=tray`
  (`src/tray/TrayApp.tsx`). It is built hidden once the full window is up, so the first click
  shows it at once. Dropping, the download prompt for a recipe's missing models and the
  drop overlay are shared with the full window (`src/state/dropflow.tsx`).

## The icon

The four stem bars, with no tile behind them. It has three states, and the window that knows
the queue reports them to the main process:

| State | Icon | Tooltip |
| --- | --- | --- |
| Nothing going on | four bars | `OpenStems` |
| Jobs queued or running | the fourth bar becomes a ring | the running track and its progress |
| Stems finished out of sight | the fourth bar becomes a dot | the track that is ready |

"Out of sight" means neither window had the user's attention when the job finished. Showing
the quick-drop window, or focusing the full window, clears it. The states differ by shape, not
only by color. Right-click gives Quick drop, Show OpenStems and Quit; a double click opens the
full app.

## Listening and being told (added 2026-11-22)

- **Click a stem to hear it.** A pill is clicked to listen and dragged to use. Only the stem
  that was clicked is fetched and decoded (`src/audio/audition.ts`), so sound comes quickly;
  the last eight decoded stems are kept. Another stem of the same song starts at the position
  the first one had reached, so the same bar can be compared. Playback stops when the window
  is put away and when another song's stems are laid out. Enter and Space do the same from
  the keyboard. The full window keeps its player with solo and mute; this one is for a quick
  check.
- **How it looks.** The playing pill takes its stem's color at once and its dot becomes three
  level bars, which move by `transform` only and stand still under reduced motion. The dot
  and the bars share one fixed slot, so starting to play moves nothing else.
- **A notification when the queue has run dry out of sight.** One per drained queue, not one
  per song: the song's name, or a count when several finished since the user last looked. It
  respects Windows' quiet hours, clicking it opens the quick-drop window, and Settings > Tray
  turns it off. Nothing is raised when either window had the user's attention.

## Staying in the tray

- **Closing the full window leaves the app running**, with the engine up, so the next drop
  starts at once. This is a setting ("Keep running in the tray", on by default) because it
  changes what the close button does. The first time, a Windows notification says the app is
  still running and how to quit. With the setting off, closing the window quits as before.
- **`--tray` starts the app without a window.** If first-run setup has not run, the full
  window opens anyway, since setup needs the user.
- **"Start with Windows"** in Settings registers the app to start at sign-in with `--tray`.
  It is off by default and exists only in an installed app.
- The shell's own preferences are in `shell.json` in the app's data folder, not in the engine
  settings: the main process needs them before the engine is up.
- **Graphics memory.** An app that stays in the tray would otherwise hold its last model on
  the GPU for days. The worker now unloads its models after ten minutes without a job; the
  next job loads its model again. `OPENSTEMS_IDLE_UNLOAD_SECONDS` changes the time, and 0
  keeps models warm for ever.

## Motion

The rules of ADR 0005 hold. The window itself appears with the animation Windows gives a
window; nothing inside it is animated on top of that. Rows, hover actions and switching which
job shows its stems change at once. One thing moves: stems that have just arrived rise in one
after another (30 ms apart, 200 ms each), because that is the moment the window exists for.
A job that was clicked shows its stems at once. A stem pill gives under the press like every
other pressable thing, and reduced motion drops the movement.

## Alternatives considered

- **Hide on blur, like a menu.** Rejected: it makes drag-and-drop impossible, as above.
- **A drop target on the icon itself.** Electron reports drops on a tray icon on macOS only.
- **A global shortcut.** Left out: it would have to be chosen around each DAW's shortcuts.
- **A transparent window with its own shadow and animation.** A plain frameless window gets
  rounded corners, shadow and animation from Windows and has no dead margin around it.

## Testing

- **Unit** (`src/test/tray.test.tsx`): placement for a taskbar on each edge, a hidden taskbar,
  a second screen and a small screen; the icon states and tooltips; the preferences file; the
  window's rows, stem pills, drags, the "just arrived" rule and following the other window.
- **End-to-end** (`e2e/tray.spec.ts`): the icon opens and hides the window inside the work
  area; a song in and stems out; both windows share recipe and queue, and the icon announces
  stems finished out of sight; closing the full window keeps the engine running and the tray
  brings the window back; with the setting off, closing quits and leaves no engine behind;
  `--tray` opens no window.
- **Engine** (`tests/test_worker.py`): the idle unload.

## What automation cannot check

- **A real drop from Explorer onto the window, and a real drag out of it.** As in ADR 0005,
  tests feed files through the file input and record the paths a drag would hand to Windows.
  Both use the same code as the full window, where they were tried by hand.
- **The login item.** Tests use a stand-in so they never write to the registry. The real call
  is Electron's `app.setLoginItemSettings`.
- **The Windows notification** on the first close; tests record that it would be raised.
