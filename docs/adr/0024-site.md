# 0024: A landing page on GitHub Pages

Status: accepted, 2026-11-24

## Context

The project had no page of its own: people landed on the README. PLAN.md does not ask for a
site, so this is an addition, not a deviation from a phase.

## Decision

- `site/` is a static page with no build tool and no dependencies: `index.html`,
  `style.css`, `main.js`, and two OFL fonts (Archivo, JetBrains Mono) with their licenses.
  `scripts/build-site.mjs` adds what it shares with the repository (`CHANGELOG.md`, the app
  icon, `docs/images/app.png` and `drums.png`), so nothing is kept twice.
- `.github/workflows/pages.yml` deploys it with GitHub's Pages actions on a push to `main`
  that touches those files, on every published release (so the changelog is current), and by
  hand. Pages is set to "GitHub Actions" as its source, not "deploy from a branch": that
  would serve `docs/` itself.
- Download links start at `/releases/latest` and are replaced by the newest release's files
  from the GitHub API in the browser. Asset names carry the version, and
  `release-mac.yml` adds the Mac files after a release is published, so a link fixed at
  build time would point at a dmg that is not there yet; the page says so while it is
  missing.
- The page asks nothing of anyone but GitHub: fonts are served with it, and there is no
  analytics and no cookie, as the app has no cloud.
- The waveforms are drawn by a seeded generator: no audio is published (rule 5).
- Copy follows the README: NVIDIA tested, AMD an untested preview, the Mac a preview run on
  one M1 Max so far.

## Consequences

- The site's facts (requirements, sizes, the Mac's first-open steps) are a copy of the
  README's and must change with it.
- The support link is one `href` in `site/index.html` (`id="support-link"`).
