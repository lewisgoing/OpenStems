# 0025: A landing page on GitHub Pages

Status: accepted, 2026-11-24

## Context

The project had no page of its own: people landed on the README. PLAN.md does not ask for a
site, so this is an addition, not a deviation from a phase.

## Decision

- `site/` is a static page with no build tool and no dependencies: `index.html`,
  `style.css`, `main.js`, and two OFL fonts (Archivo, JetBrains Mono) with their licenses.
  `scripts/build-site.mjs` adds what it shares with the repository (`CHANGELOG.md`, the app
  icon, `docs/images/app.png`, `drums.png` and `quick-drop.png`), so nothing is kept twice.
  The hero's Studio picture (`site/images/studio.png`) is the site's own: the README has no
  picture of the trimmer. It is `trim-2-part.png` from the app's screenshot run, cut above
  its folder line.
- `.github/workflows/pages.yml` deploys it with GitHub's Pages actions on a push to `main`
  that touches those files and by hand; a pull request that touches the site only builds it.
  A release needs no trigger of its own: its changelog reaches `main` before the tag, and a
  release event runs on the tag, which the `github-pages` environment does not let deploy.
  Pages is set to "GitHub Actions" as its source, not "deploy from a branch": that would
  serve `docs/` itself.
- Download links start at `/releases/latest` and are replaced by the newest release's files
  from the GitHub API in the browser. Asset names carry the version, and
  `release-mac.yml` adds the Mac files after a release is published, so a link fixed at
  build time would point at a dmg that is not there yet; the page says so while it is
  missing.
- The page asks nothing of anyone but GitHub: fonts are served with it, and there is no
  analytics and no cookie, as the app has no cloud.
- The waveforms are drawn by a seeded generator: no audio is published (rule 5).
- Copy follows the README: NVIDIA tested, AMD a preview that a user has reported working and
  the project has not run, the Mac a preview run on one M1 Max so far.
- The version the page shows before GitHub answers is `app/package.json`'s, filled in by the
  build, and the build stamps the stylesheet and script links so a browser never keeps an
  old copy.

## Consequences

- The site's facts (requirements, sizes, the Mac's first-open steps, and the README's Memory
  table, which "Will it run?" turns into a picker: `MACHINES` in `site/main.js`) are a copy
  of the README's and must change with it.
- The OpenStems Studio section (its anchor is still `#trim`) is a working copy of the editor's selection on a 16-bar demo song.
  Its names follow the app: `rangeLabel`, `rangeLength` (`app/src/lib/grid.ts`) and
  `mixLabel` (`app/src/state/mix.ts`) are copied into `site/main.js`, so a change to how the
  app names a clip or a mix changes the site too. The every-stem section's chain and figures
  (-144.9 dB, 21.6 and 25.8 dB) are ADR 0017's.
- The support link is one `href` in `site/index.html` (`id="support-link"`), set to the
  owner's Ko-fi page. Were it emptied, the button would hide and a line would say a Ko-fi
  page is coming.
- The section anchors are public addresses, listed in `docs/site.md` with what the app
  could link to.
